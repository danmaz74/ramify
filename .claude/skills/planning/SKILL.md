# Planning

Read the project's [agent instructions](../../../CLAUDE.md), the relevant
[roadmap brief](../../../docs/plans/tooling-architecture/README.md) and
[implementation workflow](../../../docs/development/implementation-workflow.md).
Load the model and architecture documents needed by the actual change.

Inspect current source and predecessor evidence before treating a capability as
available. Preserve the user's accepted choices, existing edits and plan identity.
Make unresolved contracts, owners, consumer access, fixtures and exit criteria
concrete enough to review. Follow the roadmap's iteration and handoff format.

Use the installed Studio tools for managed artifacts, following
[plan artifact guidance](../../../docs/development/cucumber-viz.md#plan-artifacts-and-prompts).
Keep ordinary plan files under this project's `docs/plans/`; do not create a
second status tree or substitute host domain/barrel conventions.

For a review request, return actionable findings with the affected case, location
and suggested correction. For an authoring request, produce the requested plan
artifacts and validate their links, consistency and acceptance coverage. State
remaining review decisions and distinguish planning validation from execution.
