- `request-handback` runs the committing combined work-item gate over the selected task owners. A failed real check remains in its gate record and sends its cause back to the same capability architect. Passing checks yield a candidate snapshot. Code, scope and design reviewer invocations read that snapshot, and their record binds the plan revision, source tree and gate. Review concerns return to the architect for a scoped repair and a new gate.
- Acceptance requires every task assignment to have submitted an in-scope result, a passing audited gate, executed selected tests in the real provider and consumer test directories, passing type and Ramify checks, and original-example dispositions with executed test associations bound to the candidate tree and project configuration. The handback's example evidence must match the current plan. A second live-tree check after review rejects concurrent source drift. Only then are provisional assignments promoted to accepted and the task handed back once.

The retained A engineer resumes its original assignment; accepting the capability does not finish A's original goal. A later request can name the accepted task it revises; the new task stores that handback reference and source revision while the earlier acceptance remains intact.

Historical workflow refusal behavior is unchanged.
