# Iteration 7: replace the old path and verify the production workflow

[Plan 16](../main-plan.md) · [Acceptance matrix](../acceptance.md)

## Prerequisites and owners

Iterations 1–6 pass their gates. Integrate harness and web under their existing
ownership; run real target work in isolated worktrees through the production
harness. Establish the actual baseline before the final comparison.

## Goal and read first

Enable the complete capability workflow for new runs. Read the source inventory
and migration sections of the main plan, both archived trial reports, the
new action contracts, current prompt manifests and full-audit request format.

## Deliverables

- Capture a new workflow/policy version. Remove new-run dispatch to the old
  contract engineer, fake-first obligations and yield-for-providers chain.
  Retain historical decoding/projections; refuse incompatible old-run execution
  with an explicit explanation. Reuse useful fake checks independently.
- Register the already tested workflow factory in production composition as
  the new-run default. Keep the fixture policy injector in testing source and
  reject public attempts to supply internal policies. Verify that iteration 4's
  task completion predicate is used on every new-run completion path.
- Update production prompts, role lists, single-session entry points and test
  fixtures so no new-run default accidentally selects the retired workflow.
  Record retirement of the separately resolved version-4 contract procedure,
  package version and corresponding manifest expectation. Apply the reviewed
  [model amendments](../model-amendments.md), including the complete glossary
  and protocol/consumer-return sections. Preserve unrelated changes.
- Create the Plan 16 audit request from the existing Plan 14 request with the
  actual baseline and relevant checks. Run baseline and final full audits;
  record exact revisions and distinguish pre-existing failures from regressions.
- Execute CA27 with Pi through the production harness and a captured bounded
  toolkit request. Every source change is a scoped engineer assignment; every
  engineer handoff has a structured result. No temporary driver or coordinator
  repair replaces production transitions.
- Establish failure-handling gate CA35 through an observed unresolved defect or
  a controlled bounded Pi stop. It may be a separate run and cannot substitute
  for delivery gate CA27. Record the two verdicts separately.
- Exercise the served browser views and archive prompts, plans, source identity,
  results, checks, audit evidence, usage, timings and unresolved findings.

## Verification and exit criteria

Run the whole CA01–CA35 matrix, final audit and real Pi/browser witnesses. The
live bounded task uses the original toolkit baseline, model and cases stated
in the main plan, plus the stronger alias/quoted-name/parity controls.
An incomplete run can establish only failure handling; successful delivery
stays open. Iteration 7 stays incomplete until both live gates pass. Iterate
on an identified harness defect and rerun its affected witness when needed.

Exit: new production runs use only the new workflow; historical inspection
works; CA27 has explicit verified handback and A continuing; CA35 has explicit
unfinished-state evidence without false acceptance.
Report diagnostic feature limitations separately from harness acceptance.
