### Retained facts (`src/session-facts.ts`, private)

The facts are one frozen plain object: the registry, the inventory, the derived areas, per-file `FileFacts` (the file's export description, its accesses in whole-pass order, the access coverage notes located in it and its resolution candidates), the assembled catalog, the linked descriptions, the model, per-access decisions (the `AccessResult` and its diagnostics in production order) and three reverse indexes: `importers` from every file an access's facts read (its target and every forwarding hop) to the files holding those accesses, `selectors` from original key to the accesses whose selections resolved to it, and `owners` from access id to file. `factBytes` is the serialization length measured at publication; the sum over the current and retained historical versions is bounded by `maxRetainedFactBytes`, and exceeding it fails the update with a `resource-limit` diagnostic in a `reported` outcome. `draftReport` drives the same `ReportDraft` a batch run drives, in the same stage order with the same inventory, catalog-coverage filter, link-invalid and model-invalid branches, access assembly, results in access order and diagnostics in production order, so `build()` yields a revision's outcome, summary and sorted lists and `finish()` yields the report with Plan 1's byte bounds and `copyReport` sharing.

### The revision step (`src/session-revision.ts`, private)

- **Classification.** `observer.apply(changes)` runs first; the revision's `changed` list is the set of observed paths whose identity differs between the observer's inputs before and after the update. An update whose named changes all had unchanged identities reports `identical: true` with the current revision and publishes no sequence. `incomplete` is delivered unpublished as a batch-shaped failure; `invalid` publishes an invalid revision whose facts carry no model, results or decisions and marks the session stale so the next update recomputes everything.
- **Path selection.** A local update whose owned source files changed takes the source side; a README-only update takes `metadata` (inventory replaced, no compiler, link or decision work, timings zero for those phases). Structural updates, changed non-owned inputs, created or deleted owned files, changed descriptions, identity changes the update does not explain, a released compiler and a stale session take a conservative `broad` path: one adapter update naming the created and deleted files followed by a separate `invalidateAll` update when a non-owned input changed, then a whole recomputation over the warm compiler, a relink and every decision. The description path of iteration 7 is therefore exact but unnarrowed in this iteration.
- **Source side.** One `adapter.update` names the changed owned files; `adapter.describe` over them returns the delta of iteration 3; the re-interpretation set is the changed files, the importers of every file in `delta.changed`, and the importers of a file in `delta.moved` whose coverage notes cite a position inside it. Per-file access facts are replaced for exactly that set. The path is `unchanged-surface` when no importer joined and every changed file's description is not in `delta.changed` and its access facts are equal by value ignoring positions; otherwise `source`.
- **Model.** The model is rebuilt when a description changed by value, an original was removed or an original changed beyond its declaration positions; the rebuild reuses `linkDescriptions`, the `maxExposurePairs` limit and `buildModel` exactly as the batch run does. When originals only moved, the retained model's and the link input's declaration evidence is replaced by the fresh catalog's declarations (canonicalized the way `buildModel` canonicalizes them) without a relink.
- **Decisions.** Accesses are decided again when their fact changed by identity (new or changed id or content) in a re-interpreted file, when the rebuilt model's record or exposure set for their selected original differs from the previous model's, or entirely when the module tree changed or no model existed before. Accesses selecting a moved original are decided again from the patched model so their evidence and diagnostic identities match a fresh pass; these position refreshes are not counted in `checked.accesses`, which is why a body edit reports zero accesses decided. An invalid link drops every decision and publishes an invalid revision whose projection has the link stage invalid and no accesses, as batch does.
- **Publication.** The compiler's reads of the update are promoted through `observer.apply([])` before the revision's `inputs` and `inputId` are read, so a revision's identity equals a batch capture of the same state. `FindingDelta` is computed over the complete diagnostic lists by identity; a diagnostic whose identity vanished and reappeared with an equal position-insensitive surface (category, code, message, file, related files, importer, original) is `positionOnly` rather than removed and added. Timings record classification, the observer's apply, the adapter update, descriptions, accesses, link, decide, publication and the total.
- **Failures.** Any error inside an update is delivered as a `reported` batch-shaped failure at the stage that was running, the published revision is kept, and the session is marked stale so the next update recomputes from the disk.

### Audit, history and lifecycle

- `verify` (`src/session-audit.ts`) recomputes every description, every access, the model and every decision from the warm compiler and compares inventory, areas, per-file descriptions, accesses, coverage and candidates, catalog, linked descriptions, link issues, model, every decision and the indexes by value. It returns `equal` or publishes the recomputed facts as a new `broad` revision and returns the differing field names. Nothing retained (an invalid state) is reported as equal.
- `report(control, sequence)` projects the named retained version; every published version's facts are retained, sharing unchanged data, until `releaseRevision` releases it; releasing the current revision is rejected and a released sequence projects null. `status()` reports the level from the adapter, the sequence, the observed input count, the retained fact bytes, the process memory and a null compiler pid. `sweep` runs `observer.reobserve` and updates when it names changes. `releaseCompiler` demotes to warm and the next update takes the broad path over the reopened compiler. `dispose` disposes the adapter and the observer, clears the versions and makes later updates `session-disposed`.

## Issues encountered and decisions taken

- **The pinned baseline engine could not load the analysis entry.** I5-01's two equality instances replay the pinned pre-Plan-5 engine sources over the built entry. With A12 active, the analysis index reaches `retained-source-analysis.js`, whose import of `AccessInterpretation` the pinned `accesses.ts` cannot satisfy, so both instances failed with an ESM link error on the first complete gate run. `plan5-baseline-loader.mjs` now serves an explicit throwing stub for that module in baseline mode; the batch replay never calls it, so the comparison is unchanged and the second run passed all 42.
- **A created file must enter the program by name before any whole invalidation.** The adapter's `invalidateAll` update ignores its `created` and `deleted` lists, and a created file also changes the identity of every directory between it and the root, which the first version of the session treated as an unexplained input change requiring `invalidateAll`; the created file was then absent from the program. The session now explains those directory observations by the created or deleted file and issues the created/deleted update before a separate `invalidateAll` update when one is needed.
- **The report stage must be marked complete before `build()`.** `ReportDraft.finish()` sets the report stage; a revision built without it reported `check: not-run`. Publication marks the stage complete, then builds.
- **Position refreshes are not counted as decisions.** The I5-06 expectation of zero accesses decided for a body edit holds while the accesses selecting the moved `inspect` original are decided again from the patched model; re-deciding through `explainImport` is the exact way to refresh their evidence and diagnostic identities, so `checked.accesses` counts only genuinely re-decided accesses and `delta.positionOnly` reports the refreshes.
- **Importers of a moved file with coverage citing it are read again.** A coverage note's identity contains the positions it cites, so a declaration move in a target file changes the notes of an importer whose unresolved selection cites that target; the source path adds exactly those importers to the re-interpretation set.
- **Adapter areas.** The adapter fixes its source areas at creation and `SourceChangeSet` carries none, so the whole recomputation disposes and recreates the adapter when the derived areas differ from the ones it was created with. No I5-06 instance exercises it; iteration 7's tag changes will, and the typescript owner may prefer an `areas` member on the change set.
- **`describe` is called once per whole recomputation.** Naming every owned file returns every description, so the cold, broad and audit paths read the adapter once rather than twice.

## Remediation after the automatic checks

The workflow's regression run reported two failures, both corrected in a follow-up commit and verified locally with the focused tests only:

- **The batch entry loaded the compiler package.** `src/tests/entry-boundaries.test.ts` requires that `ramify check --batch` loads no module of the `typescript` package; with A12 active the analysis index reached the retained adapter, which imports the compiler API statically. `session-revision.ts` now imports `retained-source-analysis.js` lazily when a session creates its adapter, so the batch path stays free of the compiler API and `check:self` still accepts the lazy import (11 owners, no finding). `src/tests/entry-boundaries.test.ts` passes on the rebuilt `dist/`.
- **Two session tests exceeded vitest's 5 s default under the parallel regression run.** Every case of `retained-session.test.ts` now carries an explicit 120 s timeout, as the compiler-bearing tests of other owners do; all 10 pass.

Two scope-review findings were raised and could not be decided from this session (the workflow requires the authenticated review surface): the throwing stub in `plan5-baseline-loader.mjs`, forced by A12 making the adapter reachable from the pinned baseline replay, and the members implemented ahead of the iteration table (`verify`, `sweep`, `releaseRevision`, historical projection, the metadata path and the broad fallback), which the `RetainedSession` contract and the I5-06 handlers' `verify()` calls require. Both are documented under Issues and Known limitations for the reviewer.

## Known limitations

- The description path is taken as `broad` (whole re-extraction over the warm compiler, relink, all decisions): exact, but not the subtree-bounded work iteration 7 fixes. The metadata path, the created and deleted file handling and the invalid-update projection are implemented conservatively and not asserted by a matrix row here.
- `SessionStatus.compiler` reports a null pid and rss: the adapter port does not expose its server, and the typescript-private evidence export is not used by toolkit source. Iteration 8 owns the worker and compiler accounting.
- The invocation parameter of `update` validates the capability set and the resolved root and configuration, replaces the echoed request and publishes a new sequence when the echo changed; `scope.invokedFrom` and `selection` remain those of the opening acquisition, which iteration 9's lease handling must settle.
- Historical fact versions are retained whole per sequence; `factBytes` sums each version's serialization measured at publication, which over-counts shared data. History budgets and eviction belong to contexts in iteration 9.
- Deadlines are the caller's: the session completes an update unless cancelled, and the synchronous compiler cannot be interrupted in the caller's thread until iteration 8's worker.
- On the reference, a body edit's compiler, description, access, link and decide phases total about 12 ms, but the observer's `apply` (116 ms) and the classification's input diffing (59 ms over two `observer.inputs` reads of 3,615 inputs) dominate the 317 ms total; the promotion of the update's compiler reads through a second `apply([])` adds to it.
