## Proposed specification patch

`/home/app/ramify-pb1-evidence/iteration8/8c/proposed-spec-patches-step1.diff`
(passes `git apply --check`), for `docs/architecture/modularity-report.spec.md`:

1. Owners table: the Git adapter and probe rows name owner
   "`analysis`, auxiliary source" and the paths under
   `subs/analysis/scripts/probes/modularity/`.
2. "Probe and Git adapter": Git execution stays outside `analysis`'s `src/`;
   the probe and adapter are `analysis`'s auxiliary source with the ordinary
   profile, import `analysis` source by relative path as same-owner source,
   cannot import its testing source and cannot be exposed;
   `tsconfig.scripts.json` compiles them and the project's `tsconfig.json`
   does not select them. This replaces "the probe neither becomes
   module-owned source nor produces outside-module warnings" and "the
   modularity probe imports `ramify.ts/analysis` from `dist/`", which the move
   makes false. The sentence "Existing probes import built package output"
   goes with it: it described the other root probes, which this
   specification does not cover.
3. Iteration 6 handoff: the candidates directory is
   `subs/analysis/scripts/probes/modularity/candidates/`.

"No projection function is exposed; `projectDependencyDiagram` is exported
only from the `ramify.ts/analysis` package entry" and "No `module.ramify`
exposure is needed while no other owner imports the projection" stay true:
the probes are analysis's own source, so no exposure was added. They would
have become false only under the alternative of exposing the projections to
the root. The specification does not name the dependency-analyzer probe, so
the patch does not either.
