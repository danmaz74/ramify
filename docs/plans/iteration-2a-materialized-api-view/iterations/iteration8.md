# Iteration 8: Daemon service, client and CLI command

**Plan:** [Plan 2A: Materialized API discovery](../main-plan.md).
**Prerequisites:** Iteration 6 publisher and iteration 7 retained/context query.
**Owners:** daemon service/validation/codec/connection, root assembly/service,
`cli`, quick environment and their tests.

## Goal

Join the revision-bound projection to transactional publication and deliver the
real `ramify materialize` command without transferring catalog content through
IPC or falling back to batch.

## Read first

- [Root service/wire](../contracts.md#root-service-and-wire),
  [CLI grammar/exits](../contracts.md#cli-grammar-and-exits) and failure table.
- Iteration 6/7 handoffs.
- Current daemon `service.ts`, validation, codec, host/connection; root
  resident assembly and quick environment; CLI arguments, check command,
  recovery/error/output patterns and compiled entry.
- Process/client and quick-testing architecture cases PC01/PC03/QT01/QT03/QT04.

## Deliverables

1. Add materialize operation/capability, exact request validation, daemon
   dispatch and compact response codec. Unsupported peers remain explicit.
2. In the daemon service, acquire one context query, call the injected publisher
   before releasing its projection slot, attach the exact context revision to
   metadata and map every context/publisher outcome without converting domain
   failures to success.
3. Extend direct and socket clients plus quick environment with the same method.
   Assert no projection entry, Markdown or details cross the wire.
4. Inject the production publisher in root resident assembly and a controlled
   publisher in tests. Preserve the existing eleven owners/eight entries.
5. Parse exactly `materialize [--from] [--all] [--root]`, add help and the
   compact human success/failure output, exits 0/1/2/130 and existing one-time
   generation recovery.
6. Connect with `start: if-needed`, open the existing whole-project context,
   request synchronized freshness, never call the batch operation and clean up
   token/connection/owned process on every outcome.
7. Add direct-service, quick, actual IPC, compiled-process, incompatible-peer,
   argument, output-failure, cancellation and import-closure tests.

## Matrix rows executed here

I2A-09: all seven leaves. I2A-10: all nine leaves.

## Verification

Run focused service/validation/codec/connection/root/CLI tests, actual socket
tests and the installed compiled-process fixture over R. Trace loaded modules
and processes to prove help/client stay lightweight and materialize uses the
daemon. Inspect generated bytes and service response independently. Stop the
owned daemon in `finally`.

## Exit criteria

The command is runnable end to end, publishes only from its named revision,
returns compact summaries, obeys exact exits/recovery and never falls back to
batch or leaks the projection onto IPC.

## Handoff

The working command and process fixture go to iteration 9 for the actual agent
workflow, full-project measurement and cross-platform evidence.
